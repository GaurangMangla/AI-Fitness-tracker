## 2. All 6 real classes now present

Unlike v1 (5 classes, `bro_split` completely absent — see `ML_TRAINING.md` §2.4 for the original discovery), **v2's dataset genuinely includes `bro_split`**: 430 of 100,000 rows (0.43%), all generated by the same unmodified dataset generator calling the now-fixed rule engine.

This isn't a fabricated or rebalanced label — it reflects the rule engine's real, current behavior: `bro_split` is a rare-but-real recommendation, matching its actual real-world niche (advanced lifters training 5 days/week with full gym access).

## 6. Regression test: Rule Engine vs. ML Engine agreement

150 fresh, out-of-sample profiles (seed=999, distinct from training data) were run through both engines directly. See `MODEL_COMPARISON.md` §4 for the full breakdown.

- **Raw agreement: 98.00%** (147/150)
- **All 3 disagreements had ML confidence below the production `ML_CONFIDENCE_THRESHOLD` (0.6)** — every one would trigger the automatic fallback to the rule engine in the actual deployed system.
- **Effective agreement, accounting for the fallback mechanism already in production: 100%.**

---

## 7. Honest limitations (unchanged from v1, still apply)

1. **This model still can only match, not exceed, the rule engine's own accuracy** — it was trained to imitate the (now-fixed) rule engine's output, not to predict a genuinely independent outcome. See `docs/ML_ARCHITECTURE.md` §3.3/§7 for the long-term path past this ceiling (real user behavioral outcome data).
2. **97-99% test accuracy still means "the model learned to approximate a deterministic function well,"** not "this model is production-ready to replace human judgment."
3. **New limitation worth naming:** this retrain-on-rule-engine-change pattern will need to repeat any time the rule engine's scoring changes again — there's no automatic detection that the model and rule engine have drifted apart; it was caught this time because someone was actively working on both. A future improvement could log agreement rate between the two engines in production (see `docs/ML_ARCHITECTURE.md` §7) specifically to surface this kind of drift automatically.
